## 1️⃣ Visão

### Problema
O contrato OpenAPI (`ScosOrganization_Company.yml`, `/v1/cnaes`), os delegates gerados, a entidade JPA `Cnae` e a tabela `SCOS_CNAE` (Liquibase) já existem, mas **não há implementação**: sem repository, sem use cases, sem impl de delegate, sem permissões no enum. Endpoints retornam `501` (default do delegate gerado).

### Objetivo
Implementar o CRUD completo de CNAE conforme UC-098 a UC-102 (`01-empresa.md`, seção 1.2), com todos os endpoints respondendo os status corretos e guarda de exclusão física.

### Fora de Escopo
- CRUD de Natureza Jurídica — outra ideia.
- CNAEs secundários da empresa (seção 1.3, UC-103/104/105).
- Alteração do contrato OpenAPI (já pronto).
- Alteração da entidade `Cnae` / tabela `SCOS_CNAE` (já prontas).

## 2️⃣ Requisitos

### Funcionais
- [ ] **RF-01**: `GET /v1/cnaes` — lista paginada (UC-098) → `200`. Autoriza `GET_CNAE`.
- [ ] **RF-02**: `POST /v1/cnaes` — cria com `code` (≤30, único em `SCOS_CNAE`) + `description` (≤255) (UC-099) → `201`. Autoriza `CREATE_CNAE`.
  - ausente/vazio → `400`; `code` duplicado → `409` `SCOS_CNAE_002`.
- [ ] **RF-03**: `GET /v1/cnaes/{id}` (UC-100) → `200`; inexistente → `404` `SCOS_CNAE_001`. Autoriza `GET_CNAE`.
- [ ] **RF-04**: `PUT /v1/cnaes/{id}` (UC-101) → `204`; `code` único excluindo o próprio `{id}` → `409`; `{id}` inexistente → `404`. Autoriza `UPDATE_CNAE`.
- [ ] **RF-05**: `DELETE /v1/cnaes/{id}` — **exclusão física** (UC-102) → `204`. Autoriza `DELETE_CNAE`.
  - `{id}` inexistente → `404` `SCOS_CNAE_001`.
  - Em uso (`SCOS_COMPANY.cnaePrincipalId = {id}` **ou** existe linha em `SCOS_COMPANY_CNAE_SECONDARY` com esse CNAE) → `422` `SCOS_CNAE_003`.

### Não-Funcionais
- [ ] **RNF-01**: Entidade já `@Auditable` — auditoria mantida.
- [ ] **RNF-02**: Respostas de erro via `ExceptionsHandler` (RFC 9457) e mensagens i18n (`scos_message_organization*.properties`).


### Fluxo Principal
```
DELETE /v1/cnaes/{id}
  → CnaeDelegate.deleteCnae
  → DeleteCnaeUseCase
      1. findById → 404 SCOS_CNAE_001 se ausente
      2. existsByCnaePrincipalId(id) || existsSecondaryByCnaeId(id) → 422 SCOS_CNAE_003
      3. repository.delete → 204
```

### Decisões Técnicas
| Decisão | Escolha | Alternativa Descartada | Motivo |
|---------|---------|------------------------|--------|
| Localização | `usecase/corporate/company/fiscal/cnae` | `catalog/` | CNAE é sub-entidade fiscal de Company; entidade vive em `company/internal` |
| Guarda de exclusão | Validação em use case (repo `existsBy...`) | Trigger DB (como `trg_block_delete_contact_type.sql`) | Erro de domínio explícito (`SCOS_CNAE_003`, 422) e testável; ⚠️ confirmar no propose se manter alinhamento com trigger |
| Erro "em uso" | Código específico `SCOS_CNAE_003` | Código genérico | Rastreabilidade (decisão do usuário) |

### Banco de Dados
- **Impacto**: ❌ Não — tabela `SCOS_CNAE` e FKs já existem via Liquibase.

## 4️⃣ Implementação

### Arquivos

**Novos**:
- `domain/.../company/internal/CnaeRepository.java` — `existsByCode`, `existsByCodeAndIdNot`, paginação, `findById`, `delete`.
- `usecase/.../company/fiscal/cnae/{Create,Update,Find,FindAll,Delete}CnaeUseCase.java` (+ `...Bean`) — interface pública + `@Service` package-private.
- `usecase/.../company/fiscal/cnae/CnaeApiMapper.java` — MapStruct entidade↔DTO.

**Modificados**:
- `domain/.../company/internal/CompanyRepository.java` — `existsByCnaePrincipalId(Long)`.
- `domain/.../company/internal/CompanyCnaeSecondaryRepository.java` — `existsBy` sobre o `cnaeId` da PK composta (confirmar nome do campo em `CompanyCnaeSecondaryPk`).
- `infrastructure/enumaration/ScosOrganizationPermission.java` — `GET_CNAE`, `CREATE_CNAE`, `UPDATE_CNAE`, `DELETE_CNAE`.
- `scos_message_organization.properties` + `_en` — `SCOS_CNAE_001` (não existe), `SCOS_CNAE_002` (code duplicado), `SCOS_CNAE_003` (em uso).

### Tarefas
- [ ] **T-01**: `CnaeRepository` + métodos de existência/unicidade.
- [ ] **T-02**: Métodos de guarda em `CompanyRepository` e `CompanyCnaeSecondaryRepository`.
- [ ] **T-03**: Use cases Create/Update/Find/FindAll/Delete (+ Beans) e `CnaeApiMapper`.
- [ ] **T-04**: `CnaeDelegate implements CnaeApiDelegate`.
- [ ] **T-05**: Permissões no enum + mensagens i18n.
- [ ] **T-06**: Testes (unit use cases + integração Testcontainers p/ unicidade e guarda de delete).

### Riscos e Edge Cases
1. Guarda de delete precisa cobrir **ambas** as referências (principal e secundário) — omitir a secundária deixa órfão.
2. Nome do campo `cnaeId` na PK composta `CompanyCnaeSecondaryPk` — verificar antes de escrever o `existsBy`.
3. Unicidade de `code` case/trim — decidir normalização no propose (alinhar com padrão de outros catálogos).
4. Precedente do trigger de ContactType: decidir no propose se a guarda fica só no app ou também em trigger (consistência do módulo).
